search

Web search across several engines, merging and reranking the results, and research digests

search sends one query to several search engines and merges their results into one list. Each engine finds pages that other engines miss. A page that several engines rank highly usually gives a useful result. Fossick uses ddgs to reach the engines. ddgs does not need API keys. search merges the lists with reciprocal rank fusion (RRF). It can then reorder the merged list by query relevance.

google loads the Google results page in a stealth browser. It is slower than search. research searches, downloads readable results, and returns a markdown digest with a citation for each source. You can pass the digest to a language model.

The ddgs client

get_ddgs returns a shared DDGS client for each timeout and proxy setting. It creates each client on first use. ddgs_env reads proxy and certificate settings from the environment. This supports search behind a corporate proxy. It reads the proxy from DDGS_PROXY, HTTPS_PROXY or https_proxy. It reads a certificate bundle from FOSSICK_CA_BUNDLE, SSL_CERT_FILE, REQUESTS_CA_BUNDLE or CURL_CA_BUNDLE.

Asking each engine

For text search, Fossick queries each engine in TEXT_BACKENDS separately. It keeps each engine’s results in that engine’s rank order. It does not use ddgs combined search. That search picks engines at random and favours Wikipedia. backends lists every ddgs engine for a category. When pages is greater than 1, Fossick asks each engine for that many result pages. It drops results on later pages when they repeat earlier results. The test checks that ranks continue across pages.

Merging the lists

Reciprocal rank fusion (RRF) merges ranked lists without using the engines’ own scores. The scores are not comparable. Each page gets 1/(k + rank) from each list that contains it. RRF adds these values. A page ranked first scores more than a page ranked eighth. A page found by several engines gets one value from each engine. k is 60 by default. It controls how much more the top ranks count than the lower ranks.

rrf treats two URLs as the same page when they differ only in scheme, www., a trailing slash or tracking parameters. It uses norm_url from fossick.quality. For each page, it keeps the longest snippet. It also keeps the fused score and engines, which lists the engines that found the page.

Reranking

Search engines use more than exact query words when they rank results. rerank reorders results by how well their title, snippet and URL match the query. It combines this relevance score with the merged score. mix sets the weight of the merged score. Its default is 0.4. A value of 1 ignores the reranker. When method is not 'none', rerank adds a rerank field with the relevance score.

method selects the scorer. 'lexical' uses BM25, a standard word-matching formula. bm25 computes scores from the result list. It does not need a stored index. 'flashrank' uses the small cross-encoder model from flashrank. The model reads the query and each result together. It matches meaning better. It needs pip install flashrank. flashrank_scores returns None when flashrank is missing. method='flashrank' then raises ImportError. 'auto' uses flashrank when installed and BM25 otherwise. 'none', the default for search, keeps the merged order.

Where and when

The best answer to many questions depends on the country. Building rules, prices and availability differ by country. Search engines use a country-language region code, such as au-en. The default region='auto' reads both parts from the query.

infer_country looks for country names, adjectives and cities in COUNTRY_WORDS. It answers only when the query names one country. A query that names two countries returns None. infer_language counts common function words in LANG_WORDS, such as “the” and “what” or “der” and “und”. It answers only when one language has the highest count and at least two matches. infer_region joins the country and language results. A query with no language signal uses the country’s usual language from COUNTRY_LANG. The default us-en fills any part that the query does not define. An English question about France gives fr-en.

timelimit keeps only recent results. Use 'd', 'w', 'm' or 'y' for the past day, week, month or year.

search

search is the main entry point. For text, it queries every engine in TEXT_BACKENDS in parallel. It merges the lists with RRF and reranks them with method. backend='google' restricts it to one engine. n cuts the final list only. It does not change the number of engines queried. Increase pages to get more candidates. With fuse=False, and for the images, news and books categories, it uses ddgs search for that category. The videos category uses search_yt to search YouTube.

An empty query returns an empty list without using the network. When every engine fails, search prints one warning per process and returns an empty list. text, images, news, videos and books are search with a category set. extract downloads one URL with ddgs. It returns {url, content}. The default content format is markdown.

cache=900 keeps a result in memory for 900 seconds. A later call with the same arguments returns that result without a request. An empty result is not kept. This prevents an outage result from being kept. fetch(cache=) uses the same memory and the MEM_MOST limit. forget() clears the memory. The default cache=0 asks the engines on every call.

google

google loads Google’s results page in the stealth browser and reads the results from it. The ranking is Google’s own. It is slower than search and needs Scrapling’s browsers. It accepts the same region and timelimit as search. The country biases the ranking. It does not exclude other countries. Google applies the time limit with its own filter. The results have the same fields as search. The snippet is in content. When Google returns no results, google returns an empty list. When the browser fails, it returns an empty list and prints a warning.

research

research turns a question into readable sources in five steps:

  1. plan, from fossick.quality, splits a question with several parts into one search per part. It keeps the original question as the first search.
  2. Each search uses search, or google when engine='google'. research interleaves the results by taking one result from each search in turn.
  3. The default curated=True makes curate remove sites that copy other sites. It also moves authoritative sources up. research drops copycats before it downloads pages.
  4. research downloads candidates in order with fetch(auto=True). Each batch contains as many pages as needed to reach n. It stops after it gets n pages with at least 400 characters of readable markdown. A failed, blocked or short page goes into dropped with its reason. The next candidate replaces it.
  5. With focused=True, focus reduces each page to about chars characters from passages that best answer the question.

It returns a dictionary with query, sources, digest, dropped, region, curation and plan. Each source contains its title, href, working fetch tier, publication date, answered queries and markdown in md. The digest joins the sources with ---. Each source has its title, URL, publication date when known and the question part it answers.

page_date, usable and focus also work on their own. page_date finds a page’s publication date and returns YYYY-MM-DD, or None. It reads JSON-LD data, <meta> tags named in DATE_META, a <time> element or a /2018/09/ URL. usable checks for a 200 response, no bot wall and at least min_chars characters of readable markdown. min_chars=0 skips the length check. focus keeps passages that answer a query. It keeps opening blocks within 30% of the character budget. It then adds the highest-scoring blocks. It returns them in their original order and uses … for gaps.
