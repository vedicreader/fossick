fossick

Web search, page fetching, crawling and browser automation for Python programs and AI agents

fossick gets text off the web and into a program. You give it a search query, a URL, an arXiv id, a YouTube link, a GitHub repository or a local file, and it gives back markdown that a person or a language model can read. It was written for AI agents that need to look things up, so its functions return plain data (strings, lists and dictionaries) that can be printed or passed to a model as they are.

The library works in layers. search sends a query to several search engines at once and merges their answers into one ranked list. read takes a single target and returns its text. Under read, fetch downloads a page and to_md turns its HTML into markdown. Many sites refuse plain downloads from scripts, so fetch can also load a page in a headless browser, in a stealth browser built to pass bot checks, or in a copy of Chrome you have logged in to. For pages that need clicking and typing, cdp_connect drives that Chrome directly. Everything here is also available from the shell as the fossick command and to agents as an MCP server.

Install

uv add fossick

Searching and plain downloads need nothing else. Rendering JavaScript, the stealth fetcher and google run a headless browser through scrapling. If those calls raise BrowserUnavailable, run scrapling install to download its browsers. The browser automation in fossick.cdp drives your installed Google Chrome.

Quick start

Three calls cover most uses. search returns a list of results, each a dictionary with the page’s title, its URL in href and a snippet in body. score is the merged ranking score, and engines names the search engines that returned that page. method='flashrank' reorders the results with a small relevance model, which needs pip install flashrank; without a method the merged order is kept.

results = search('koshas github fts semantic code graph', method='flashrank', n=5)
for r in results: print(r['score'], r['engines'], r['title'], r['href'])

One function for every source

read is the function to reach for when you have a target and want its text. It first calls what_is to decide what the target is, and the answer names the reader it will use: dir for a local folder, file for a local file, arxiv for an arXiv URL or id, youtube for a YouTube link, github for a repository, ghfile for a file on GitHub, pdf for a URL ending in .pdf or /pdf, and web for any other http or https URL. A path that exists on disk wins over every URL rule.

Whatever the reader, the result has the same seven fields:

field holds
ok True when the reader produced content
kind the reader used, one of the names above
title the title, or the first heading of the text
source the URL, or the absolute path of a local file
text the content as markdown
skipped why nothing was read, when ok is False
meta details from that reader, such as the authors of a paper or the HTTP status of a page, and the time it was read

Here read opens this repository’s own README:

target = str(repo_root()/'README.md')
assert what_is(target) == 'file'
result = read(target)
assert sorted(result) == ['kind', 'meta', 'ok', 'skipped', 'source', 'text', 'title']
assert (result.ok, result.kind, result.title) == (True, 'file', 'fossick')
assert '# fossick' in result.text and result.skipped is None
result.kind, result.title, result.ok

A folder or a GitHub repository is a tree of files rather than one document, so read does not turn it into text. It returns ok=True with an empty text and puts the local path in meta['path'], and the caller decides which files to open. For a GitHub repository that path is a fresh clone in fossick’s cache. With pages=True, a PDF comes back as a list of (page_index, text) pairs, counted from 0, so that a citation can point at a page.

Sometimes a target is recognised but yields nothing: a site serves a bot check instead of the page, a YouTube video has no English captions, or a URL that looked like a PDF returns something else. read reports these with ok=False and a reason in skipped, and does not raise. It raises ValueError only when the target is none of the kinds above.

Modules

notebook what it covers
00_core downloading pages (fetch, crawl), HTML to markdown (to_md), the readers for arXiv, GitHub, YouTube and PDFs, finding the JSON API behind a page, and read
01_cdp driving Chrome through the DevTools protocol: page snapshots for agents, filling forms, running a list of steps, capturing network requests
02_search web search across several engines, merging and reranking results, google, and research
03_cli the fossick shell command
04_mcp the MCP server that offers fossick’s functions to coding agents
05_shop adding products to a shopping cart and filling checkout forms on a live store
06_quality choosing which search results are worth reading: removing copycat sites, preferring authoritative ones, and splitting a long question into several searches

Common calls

search('query', n=10, region='auto', timelimit='y')   # results from the past year
research('query', n=5)                    # search, read the top pages, return a digest that cites them
fetch(url, auto=True)                     # try stronger download methods until one is not blocked
crawl(url, max_pages=5, same_domain=True) # follow links from url, staying on its site
google('query', n=10)                     # Google's own ranking, through the stealth browser
cdp = await cdp_connect(); pg = await cdp.open_page(url); print(await pg.snapshot())

From the shell: fossick search "q", fossick fetch URL --auto, fossick research "q". For agents: uvx fossick-mcp, or fossick-mcp --http to serve over HTTP instead of standard input and output.

A logged-in Chrome

Some pages are only shown to a logged-in user. fossick reaches them through a separate copy of Chrome that runs with remote debugging switched on, on port 9223, with its own profile in ~/.cache/fastcdp/cdp-chrome. cdp_connect starts it the first time it is needed. Log in to a site once in that window and the cookies stay in the profile, so later calls such as fetch(url, session=True) arrive logged in. fetch(url, auto=True) and read fall back to this Chrome when every other method is blocked.

To start it by hand in a visible window, for logging in, run await cdp_setup(headless=False). The fastcdp-setup command, installed with fossick’s fastcdp dependency, adds a launcher for the same Chrome and profile to your applications.
