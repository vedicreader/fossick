cdp

Driving Chrome from Python: page snapshots for agents, forms, step lists, network capture and cookies

Some pages need a login, a button click or a filled form before they show useful content. A plain download cannot do these actions. This module controls Chrome through the Chrome DevTools Protocol (CDP). CDP is the interface used by Chrome developer tools. The module uses fastcdp for the connection.

The module uses one Chrome process for a long time. This Chrome is separate from the Chrome that you use for browsing. The debug Chrome listens for remote control on port 9223. It uses a separate profile. The default profile is ~/.cache/fastcdp/cdp-chrome. A site login in the debug Chrome remains after a restart.

Function What it does
cdp_setup Starts the debug Chrome and waits until it answers.
cdp_connect Connects to the debug Chrome. It starts the Chrome first when none is running.
cdp_ws Returns the websocket address of the debug Chrome. scrapling’s browser fetchers accept it as cdp_url.
cdp_app Opens a URL in the debug Chrome as an app window, with no tabs or address bar.
debug_ready Returns True when the debug Chrome is up. It never starts the Chrome. It asks the DevTools endpoint for /json/version, because Chrome opens the port a moment before it can answer there.

When a Chrome already listens on the port, cdp_connect and cdp_ws use it. The headless and extra_flags arguments then have no effect.

The functions in this module are async. Call them with await. In synchronous code, wrap them in syncy, as the examples do. Most of them are methods that this module adds to the CDP connection and Page classes of fastcdp. These Page methods are the main ones:

Method What it does
snapshot Returns a short text map of the controls on the page, for an agent.
fill_form, act Operate those controls by their visible labels.
calls Records the network requests that the page makes.
md Returns the live page as markdown.

Managing the debug Chrome

Plain HTTP requests can inspect Chrome’s DevTools endpoint. /json/version describes the browser. /json/list lists its open tabs. The first cell prints both.

The second cell closes a tab, quits the browser and starts it in a visible window with cdp_setup(headless=False). Use the visible window to log in to a site. The profile keeps the cookies after later restarts.

App windows

cdp_app opens a URL in the debug Chrome as an app window without tabs or an address bar. Use it for a local web app. It reuses the running browser. All windows share the same profile and logins. When no browser is running, it starts a visible browser and waits up to wait seconds.

cdp_app returns a dictionary with these keys:

Key Value
ok True
url, port The arguments
profile The profile folder
reused True when a browser was already running
target The id of the new window, or None when Chrome has not listed it within wait seconds (at most 5)

The first test checks the launch flags without starting a browser. The second runs cdp_app with Chrome stand-ins.

# Check `cdp_app` flags for a visible app window and the persistent profile. Do not launch a browser here.
flags = _chrome_flags(9223, _profile_dir(), False, ['--app=http://alpha.localhost:5001/'])
assert '--app=http://alpha.localhost:5001/' in flags
assert '--headless=new' not in flags                  # A hidden app window cannot be used here.
assert f'--user-data-dir={_profile_dir()}' in flags   # Use the same profile as `cdp_setup` so logins remain available.
assert str(_profile_dir()).endswith('cdp-chrome')
assert _profile_dir('~/x') == Path.home()/'x'         # `user_data_dir` takes priority, and `~` expands.
# Run `cdp_app` with a stub browser. Reuse Chrome and report its target.
# Rebind this notebook's names because `cdp_app` resolves them at call time.
# Patching `fossick.cdp` would not change the definitions in these cells.
import httpx, subprocess as _sp

_saved = (debug_ready, _sp.Popen, httpx.get)
launched = []
class _Targets:
    def json(self): return [{'id': 'target-1', 'url': 'http://alpha.localhost:5001/'}]
try:
    debug_ready = lambda port, host='127.0.0.1': True     # A debug Chrome is already running.
    _sp.Popen = lambda args, **kw: launched.append(args)
    httpx.get = lambda url, **kw: _Targets()
    r = cdp_app('http://alpha.localhost:5001/', wait=1)
finally:
    debug_ready, _sp.Popen, httpx.get = _saved

Recording network requests

calls records requests sent by a page. It always opens a new tab. With a url, it loads the page and listens for tail seconds after the load. Without a url, it listens for twice tail seconds.

calls returns a dictionary keyed by request id. Each value is a request whose URL matches pattern. The request id is in rid. When Chrome still has the response, the value also has its body under response_body. replay_xhr in fossick.core sends a recorded request without the browser.

cdp_cookies exports cookies from the debug Chrome. Pass a URL or domain to get cookies for that site. By default, it returns a list in the format accepted by Playwright and scrapling as cookies=. With as_dict=True, it returns {name: value}. fetch(url, session=True) calls cdp_cookies and sends the cookies with the request. This sends your logged-in session.

Acting on a page

An agent needs to know which page elements it can click or edit. The HTML of a full page is too long to read. snapshot builds a short view from the accessibility tree. Screen readers use this tree to describe the page. Each control becomes one line, [#id] role "name", such as [#42] button "Add to cart". Chrome assigns the id to the element. With interactive=False, snapshot also lists headings, forms and other landmarks.

type_text clears a field before it types. fastcdp’s fill_text adds text to the existing field value. click_settle clicks and waits for the page to settle. It does not fail when a click on a single-page app does not navigate.

fill_form takes a dictionary of {label: value}. It finds each field by its visible label or name. It types into text fields and selects options in drop-downs. With submit, it clicks the button or link with that name. It returns a new snapshot. It raises ValueError when no field matches a label or no button or link matches submit.

ax_diff compares two snapshots and lists added or removed lines. It ignores element ids because navigation changes them. It shows the action’s changes or (no change).

The next methods use CSS selectors. Use them when you know the page markup. node_for returns the id of the first matching element or None. click_sel clicks an element. fill_sel types into an element. Both raise ValueError when no element matches. eval_json calls a JavaScript function with Python arguments converted to JSON.

act runs a list of steps in order. Use it for a planned page flow. Each step is a tuple:

Step Action
('goto', url) Load the URL.
('fill', label, value) Type the value into the field with that label.
('click', label) Click the button, link or element with that name.
('select', label, value) Choose an option in a drop-down.
('wait', text) Wait until the text appears.
('wait_sel', css) Wait until an element matches the selector.
('read', css) or ('read', css, label) Read the matching part of the page as markdown.

act returns a dictionary with the markdown from each read step. The key is the label or the selector when the step has no label. An unknown step raises ValueError.

Screenshots and annotation

collect gathers screenshots while a person browses. It adds a bar with capture and done buttons to the page. Each capture hides the bar before it takes a screenshot.

collect stops when one of these events occurs:

  • The person presses done.
  • count screenshots have been taken.
  • tout seconds have passed.
  • The stop event is set.

With every_n, collect also takes a screenshot every every_n seconds without a button press. With save_dir, collect saves each screenshot there as a PNG file named from prefix. The default prefix is the page title. It returns a list of (image, path) pairs. Without save_dir, it returns a list of images.

BUTTON_JS, HIDE and SHOW draw, hide and show the bar.

annotate lets a person point to page elements. The page outlines and numbers each clicked element. An agent can use this information to ask which button or field the person means.

annotate ends when the person presses done, tout seconds pass or the stop event is set. It then takes a screenshot with the numbers. It returns (img, selected). selected is a list with one dictionary for each element. Each dictionary has the keys n, role, name and selector (a CSS selector). With save_dir, annotate also saves the screenshot as a PNG file named from prefix.

annotate injects the scripts ANNOTATE_JS, ANNOTATE_BAR_JS and ANNOTATE_CLEANUP_JS.
