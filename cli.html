The fossick shell command

Installing fossick adds a fossick command, so a shell script or an agent with only a terminal can use the library. It takes a command name and then that command’s options:

fossick search "sqlite wal mode" --n 5
fossick fetch https://example.com --auto
fossick read-arxiv 1706.03762 --source
fossick research "what is the raft consensus algorithm" --n 3

Each command is a thin wrapper over the Python function of the same name and takes the same arguments as options, with underscores written as hyphens: max_pages becomes --max-pages. Output is readable markdown by default. --as-json prints JSON instead, for piping into other programs. fossick <command> --help lists a command’s options, and fossick alone lists the commands.

One default differs from Python: fossick search reranks with BM25 (--rerank lexical), where search in Python keeps the merged order.

The command table

CMDS maps each command name to its function. main is the entry point the fossick script calls: it takes the command name off the command line, parses the remaining options against that function’s signature, and runs it. An unknown command prints the list of commands and exits with status 1.

Tests

The first cell checks that every command is registered and that the options agents rely on exist. The second runs research against live services and is skipped by the tests.

# end-to-end: the research CLI runs against live services and prints a cited corpus
import io
from contextlib import redirect_stdout
buf = io.StringIO()
with redirect_stdout(buf): research.__wrapped__('what is the raft consensus algorithm', n=2)
out = buf.getvalue()
assert out.startswith('# Research:') and 'http' in out
print(out[:300])
from pathlib import Path
# The CLI's `search`, `fetch`, `crawl` and `research` share names with the library's, and nbdev's doc links resolve a
# bare name to the CLI page first, so index.ipynb links them by hand; the README must not send readers to cli.html.
