shop

Add products to a cart and fill checkout forms on a live store.

Reading the page in the browser

SHOP_JS is a script that the module injects into the store page. It finds these items:

  • product cards, add-to-cart buttons, and quantity controls
  • the cart count, subtotal, and cart lines
  • form fields
  • blockers such as cookie banners

The script reads links, text, and common markup from the page. It has no rules for one store. Page navigation removes the script. The Python code injects it again when needed.

Site hints

SITES stores facts that the page does not show. These facts include search and cart URLs for some stores. They also include notes such as “pick a store first”. site_hint returns the entry for a URL host, or {} for an unlisted store. Unlisted stores also work. The module searches them through the store’s search box.

Reading the store

These methods are added to fastcdp’s Page. Each method returns plain data.

shop_prep injects SHOP_JS when the page has no copy of it. It returns the store platform: shopify, woocommerce, bigcommerce, magento, next, or generic.

shop_products lists the products on the page. Each product has a number in i. Use that number or the title to choose a product. On a product page, the main product comes first. The other products have the related mark.

shop_cart reads the cart item count and subtotal. It uses Shopify’s /cart.js when available. It reads the page for other stores. The source key identifies the source. shop_lines reads the cart lines from the cart page.

shop_blockers names blockers such as cookie-banner, location-required, login-required, captcha, and modal-open. shop_dismiss clicks cookie banners and closable pop-ups.

A request that cannot run raises ShopError. For example, a product number that is not on the page raises this error. The error lists the available choices.

Actions that check their result

shop_add adds a product selected by number or title. It returns ok, how, the product, and the cart before and after readings.

ok Meaning
True A cart signal changed. A cart signal is the item count, subtotal, cart lines, or a new confirmation message. how names the signal as count, subtotal, lines, or the confirmation message.
False Nothing changed. error gives the reason.
None The page has no cart count or subtotal to compare. The add is not confirmed.

A title must match a product title exactly or occur within a product title. An exact match takes priority. A Shopify product can have variants such as sizes. When several variants are in stock and you pass no variant, shop_add returns need='variant' and the in-stock variants. It does not choose a variant. A product with one in-stock variant uses that variant.

shop_cart_page opens the cart page and returns the cart with its lines. shop_qty sets the quantity of a line. shop_remove removes a line. Both methods check the cart as shop_add does.

Checkout forms

shop_fields lists every visible form field on the page. Each entry has the field number i, the label, the autocomplete token and the current value. A drop-down entry also lists its options. shop_fields never returns password values.

shop_fill fills a form from a profile dictionary. The standard keys are first_name, last_name, email, phone, address1, address2, city, state, postcode, country, company, notes and the card_* keys. match_fields decides which field each key goes into. It checks the field’s autocomplete token first, then its name or id, then its label. It uses the words in FIELD_MAP, which include Australian wording such as “suburb” and “postcode”. Each field is used for one key at most.

A numeric key, such as '7', fills field number 7 from shop_fields. Use it for choices that have no standard key, such as size or delivery time.

After the fill, shop_fill reads the form again and reports whether each field holds the value. shop_set sets one field by its number.

shop_fill(submit=...) clicks a button or link by its name after the fill. A name that matches PAY_RX, such as “Pay now” or “Place order”, needs confirm=True. Without it, shop_fill raises ShopError and fills nothing.

Shop

The methods above are asynchronous and require a Page. Shop wraps them as synchronous methods with shorter names: platform, products, cart, cart_page, lines, add, set_qty, remove, fields, set, fill, blockers, dismiss, snapshot, and md. The return type depends on the method. platform, snapshot, and md return strings. The other listed methods return dictionaries or lists.

Shop also has goto, open, find, and search. search tries the store search URL, the Shopify search page, and the page search box in that order.

shop(url) opens a session. It connects to the debug Chrome and starts it when needed. It reuses a tab that an earlier shop call left open on the same store. With resume=True, it keeps that tab on its current page instead of going to url. The fossick shop --add 0 command uses this tab to act on results left by a previous --search command.

These cells run against Allbirds, a Shopify store, and CERES Fair Food, a custom store. The tests skip these cells.

s.search('tree runner')[:2]
# No size is chosen when several sizes are in stock.
r = s.add(0)
r.get('need'), [v['name'] for v in (r.get('variants') or [])][:3]

Limits

fossick does not solve captchas. It never clicks a payment button unless the call passes confirm=True. Store pages change over time. The in-page script can stop finding a store’s controls. Every action checks the cart and reports what it found. It does not assume that a click worked.
