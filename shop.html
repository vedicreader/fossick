shop

Adding products to a cart and filling checkout forms on a live store

Reading the page in the browser

SHOP_JS is a script that the module injects into the store’s page. It finds these items:

  • the product cards, and the add-to-cart button and quantity control on each card
  • the cart count and subtotal, and the cart lines
  • the form fields
  • anything in the way, such as a cookie banner

The script reads the page’s links, text and common markup. It has no rules written for a single store. A page navigation removes the script. The Python code injects it again when it is needed.

Site hints

SITES holds facts that the page does not show: the search and cart URLs of some stores, and notes such as “pick a store first”. site_hint returns the entry for a URL’s host, or {} for a store that is not listed. Unlisted stores also work. The module searches them through the store’s own search box.

Reading the store

These methods are added to fastcdp’s Page. Each returns plain data.

shop_prep injects SHOP_JS when the page has no copy of it. It returns the platform the store runs on: shopify, woocommerce, bigcommerce, magento, next or generic.

shop_products lists the products on the page. Each product has a number in i. You choose a product to add with that number or with its title. On a product’s own page the main product comes first. The other products on that page are marked related.

shop_cart reads the cart’s item count and subtotal. It uses Shopify’s /cart.js when the store has one and the page otherwise. The source key says which. shop_lines reads the lines on the cart page.

shop_blockers names what is in the way: cookie-banner, location-required, login-required, captcha or modal-open. shop_dismiss clicks through cookie banners and closable pop-ups.

A request that cannot be carried out raises ShopError. An example is a product number that is not on the page. The error lists the choices that were there.

Actions that check their result

shop_add adds a product, chosen by number or by title. It returns ok, how, the product, and the cart before and after.

ok Meaning
True A cart signal changed. A cart signal is the item count, the subtotal, the cart lines or a new confirmation message. how names it: count, subtotal, lines, or the confirmation message.
False Nothing changed. error gives the reason.
None The page shows no cart count or subtotal to compare. The add could not be confirmed.

A title must match a product title exactly, or else it must be part of a title. The exact match wins. A Shopify product can have several variants, such as sizes. When several variants are in stock and you pass no variant, shop_add returns need='variant' and the list of variants in stock. It does not pick one. A product with one variant in stock uses that variant.

shop_cart_page opens the cart page and returns the cart with its lines. shop_qty sets the quantity of a line. shop_remove removes a line. Both check the cart in the same way as shop_add.

Checkout forms

shop_fields lists every visible form field on the page. Each entry has the field number i, the label, the autocomplete token and the current value. A drop-down entry also lists its options. shop_fields never returns password values.

shop_fill fills a form from a profile dictionary. The standard keys are first_name, last_name, email, phone, address1, address2, city, state, postcode, country, company, notes and the card_* keys. match_fields decides which field each key goes into. It checks the field’s autocomplete token first, then its name or id, then its label. It uses the words in FIELD_MAP, which include Australian wording such as “suburb” and “postcode”. Each field is used for one key at most.

A numeric key, such as '7', fills field number 7 from shop_fields. Use it for choices that have no standard key, such as size or delivery time.

After the fill, shop_fill reads the form again and reports whether each field holds the value. shop_set sets one field by its number.

shop_fill(submit=...) clicks a button or link by its name after the fill. A name that matches PAY_RX, such as “Pay now” or “Place order”, needs confirm=True. Without it, shop_fill raises ShopError and fills nothing.

Shop

The methods above are async and need a Page. Shop wraps them as plain synchronous methods with short names: platform, products, cart, cart_page, lines, add, set_qty, remove, fields, set, fill, blockers, dismiss, snapshot and md. Each takes simple arguments. The return type depends on the method. platform, snapshot and md return strings. The other listed methods return dictionaries or lists.

Shop also has goto, open, find and search. search tries the store’s known search URL, then Shopify’s search page, then the search box on the page, in that order.

shop(url) opens a session. It connects to the debug Chrome and starts it when needed. It reuses a tab that an earlier shop call left open on the same store. With resume=True it leaves that tab on its current page instead of going to url. The fossick shop --add 0 command uses this to act on the results that a previous --search command left on screen.

Limits

fossick does not solve captchas, and it never clicks a payment button unless the call passes confirm=True. Stores change their pages over time and the in-page script may stop finding a store’s controls, which is why every action checks the cart and reports what it saw rather than assuming the click worked.
