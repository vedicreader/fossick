How we cut our build time in half

By Ana Ruiz · 4 November 2026 · 6 min read

Our CI pipeline took 42 minutes on a good day. Engineers pushed a change, went for lunch, and came back to a red build. This post describes the three changes that brought it down to 19 minutes.

1. Cache the dependency layer

Most of the time went to installing the same packages again. We moved the install into its own layer, keyed by the hash of the lock file:

- uses: actions/cache@v4
  with:
    path: ~/.cache/uv
    key: uv-${{ hashFiles('uv.lock') }}

2. Split the test suite

We ran the tests on four machines with pytest -n 4 --dist loadfile. Tests that share a database fixture stayed on the same machine.

The slowest test file decides the build time. Find it first.

— our build engineer

3. Stop building what did not change

  1. List the packages that a commit touches.
  2. Build only those packages and the packages that depend on them.
  3. Keep a full build every night, so that nothing is missed.

The results, before and after:

StageBeforeAfter
Install14 min2 min
Tests24 min13 min
Package4 min4 min
