core

Downloading pages, turning them into markdown, crawling sites, and reading arXiv, GitHub, YouTube and PDF sources

This module holds everything fossick does with a single URL or file. fetch downloads a page and to_md turns its HTML into markdown. crawl follows links from one page to the next. find_xhr and paginate_api find the JSON API a page loads its data from and read it directly. Separate readers handle arXiv papers, GitHub repositories, YouTube videos and PDFs, and read, at the end of the notebook, picks the right one for any target.

Turning HTML into markdown

A downloaded page is mostly markup that a reader does not need: navigation bars, scripts, styles and advertisements. to_md strips that away and returns the text as markdown. It accepts either a raw HTML string or a response returned by fetch, and with sel it converts only the part of the page that matches a CSS selector, such as sel='article'. html2md does the same for a string alone, and html_title returns a document’s title.

By default to_md and html2md run readability, the article extractor behind browser reading modes. It finds the main article and drops everything around it, which is what you want for a page fetched from the web. It can also drop parts of a document you meant to keep, such as section headings. For a page someone saved on purpose, or a local HTML file, pass readability=False. The whole document is then converted, and only scripts, styles, noscript and template blocks and HTML comments are removed. Downloading pages

Refusing private addresses

A program that fetches URLs chosen by an AI agent can be tricked into fetching addresses inside your own network, such as a router’s admin page or a cloud server’s metadata service, which hands out credentials. This is called server-side request forgery. check_url refuses any URL that is not http or https, any host name such as localhost or metadata.google.internal, and any host that resolves to a private, loopback, link-local or other non-public address. It raises BlockedURL, whose message names the two ways round it: pass allow_private=True to one call, or set the environment variable FOSSICK_ALLOW_PRIVATE=1 for the whole process. Every download in fossick goes through get_page, which runs this check first.

Downloading one page

get_page is the single function every download passes through. It runs check_url, then downloads the page in one of four ways. By default it sends a plain HTTP request. heavy=True loads the page in a headless browser so that its JavaScript runs. stealthy=True uses scrapling’s stealth browser, which is built to pass bot checks such as Cloudflare’s. session=True uses the logged-in Chrome described in fossick.cdp, with its cookies. The browsers are imported only when first needed, and if they cannot be loaded get_page raises BrowserUnavailable instead of quietly returning nothing.

http_get and http_post are get_page with the method set and a 30 second timeout. http_page sends a plain request with any of GET, POST, PUT or DELETE and skips the address check, so use it only for URLs your own code chose. Most callers want fetch, below, rather than any of these.

fetch

fetch is the function most code should call to download a page. It wraps get_page and returns scrapling’s response object with two attributes added: html, holding the page or only the part matching sel, and xhr, holding the background requests recorded when capture_xhr=True. The response also has status, url, and a json() method for JSON replies.

Choosing the right download method by hand is guesswork, so auto=True tries them in turn: plain HTTP, then the headless browser, then the stealth browser, then the stealth browser through the logged-in Chrome. It stops at the first response that is not a bot wall and records the method that worked in tier, or 'blocked' if none did. Each failed attempt and its reason is kept in errs.

browser_session is for downloading many pages with a browser. Starting a browser takes seconds, so instead of one per URL it opens one for the length of a with block and gives you a fetch-like function that reuses it.

Bot walls

Many sites put a challenge page in front of their content for visitors they think are scripts. Cloudflare’s “Just a moment” page and the Anubis proof-of-work page are common examples. The challenge often arrives with status 200, so it looks like a successful download. fossick treats a response as blocked when its status is 401, 403, 429, 503 or 530, when its HTML contains the marker of a known challenge or captcha widget, or when it is a 200 response with less than 200 characters of HTML. The tests below check these rules, including that a page which only mentions the word captcha is not counted as blocked.

The cells after that run against real sites and are not run by the tests. They show a Cloudflare and an Anubis wall being detected, auto=True stopping at the plain tier for a page that needs nothing more, browser_session reusing one browser for two pages, and session=True going through the logged-in Chrome.

# A site behind Cloudflare: a plain fetch hits the bot wall, and _blocked() flags it for escalation
cf = fetch('https://www.scrapingcourse.com/cloudflare-challenge', verify=False)
assert cf.status == 403, f'expected a Cloudflare 403 challenge, got {cf.status}'
assert _blocked(cf) is True            # fetch(auto=True) escalates from here (heavy -> stealthy -> session)
print('cloudflare:', cf.status, '| blocked?', _blocked(cf))
# A site behind Anubis (proof-of-work bot wall): _blocked() now recognizes it, so fetch(auto=True) escalates
an = fetch('https://anubis.techaro.lol/', verify=False)
assert 'making sure' in an.html.lower(), 'expected the Anubis challenge page'
assert _blocked(an) is True            # Anubis markers are in _BLOCK_MARKERS -> auto escalates past this wall
print('anubis wall detected by _blocked?', _blocked(an))
# regression: a normal page that merely *mentions* captcha must NOT read as a bot wall.
# Wikipedia embeds hCaptcha config keys in its page JS -- the word is there, but there's no challenge widget.
wiki = fetch('https://en.wikipedia.org/wiki/Anubis', verify=False)
assert wiki.status == 200 and 'captcha' in wiki.html.lower()   # the word IS present on the page...
assert _blocked(wiki) is False   # ...but _BLOCK_MARKERS matches captcha *widgets* (g-recaptcha/h-captcha/...), not the word
# fetch(auto=True): walks plain->heavy->stealthy->session, stops at the first unblocked tier, tags .tier
plain = fetch('https://example.com', auto=True, verify=False)
assert plain.status == 200 and plain.tier == 'plain'   # a static page needs no escalation
print('example.com ->', plain.tier)
# browser_session(): open ONE browser, reuse it across fetches (skips per-URL relaunch)
with browser_session() as bf:
    a = bf('https://example.com')
    b = bf('https://httpbin.org/html')
assert a.status == 200 and b.status == 200
assert len(a.html) > 0 and len(b.html) > 0
# fetch(session=True): route through the persistent debug Chrome, reusing its logged-in cookies
pg = fetch('https://httpbin.org/headers', session=True)
assert pg.status == 200
print(pg.html[:200])

Crawling and batches

crawl visits pages breadth-first, starting from one URL and following the links that match follow_sel, until it has visited max_pages pages. By default it stays on the starting site. It returns the responses that came back with status 200, and a page that fails to download is reported and skipped. delay waits between requests so as not to load a small site heavily. For crawls with heavy or stealthy, one browser is kept open for the whole crawl unless reuse=False.

PDFs and arXiv papers

get_pdf downloads a PDF, or reads one from disk, and returns it as a PdfDocument from pdf_oxide, or None when the bytes are not a PDF. It decides by looking for the %PDF- signature at the start of the file, not at the URL, because arXiv serves papers from URLs with no .pdf ending. It also passes the small proof-of-work check that the NCBI PubMed Central archive puts in front of its PDFs. With save_path set to a folder or a file name, it keeps a copy of the file. The examples download two papers from the Self-Determination Theory site and print the start of their text.

read_arxiv takes an arXiv URL, of either the abstract page or the PDF, or a bare id such as 2306.14881. It returns the paper’s title, authors, summary, published date, link, pdf_url and pdf_path. By default it also saves the PDF in save_dir. With source=True it adds the full text of the paper as markdown under source. The metadata is cached on disk, so asking for the same paper again makes no request; force=True fetches it afresh.

GitHub

gh_clone returns a local copy of a repository. The first call clones it into fossick’s cache folder, over HTTPS first and then SSH, so a private repository works if you have an SSH key. Later calls fetch and reset the clone to the latest commit. Git runs with /dev/null as stdin, so it never reads the caller’s terminal. A local path is returned as it is, so code that accepts a repository can accept a folder on disk too. read_gh_repo reads files out of that clone, by default the README, pyproject.toml and every Python file, and returns {path: text}; its results are cached for an hour. read_gh_file reads one file from its GitHub page URL by downloading the raw file. It returns source code exactly as written and converts the file to markdown only when GitHub serves HTML.

Finding the API behind a page

Many modern pages arrive nearly empty and then load their data with background requests from JavaScript, called XHR or fetch calls, which usually return JSON. Reading that JSON directly is faster and more reliable than scraping the rendered page. find_xhr loads a page in a headless browser, records the background requests it makes, and returns each one whose URL matches pattern as a dictionary with url, content_type and the decoded data. With session=True it records the requests through the logged-in Chrome instead, and each result also carries a capture. replay_xhr sends a captured request again as a plain HTTP call with the browser’s cookies, which is how you call an API that needs you to be logged in without keeping a browser open.

pattern can be a regular expression, such as .*products.*, or a shell-style glob, such as *products*. compile_pattern accepts both: it tries the text as a regular expression and, when that is invalid, reads it as a glob.

An API rarely returns its records at the top level of the JSON. They might be under results, or several levels down at data.products.items. json_records finds them by searching the whole payload for the longest list of dictionaries, and with_key=True also tells you which key held it.

paginate_api reads every page of a paged JSON API. It sends the request repeatedly, raising the page number in page_field each time, and stops when a page comes back empty or shorter than the page size, or after max_pages pages. It finds each page’s records with results_field if you name one and json_records if you do not. With save=True each page is written to a file, and a later run reads the saved pages instead of fetching them again.

YouTube

These three functions use yt-dlp. search_yt searches YouTube and returns a list of result dictionaries. read_yt returns one video’s details and its transcript, built from YouTube’s English automatic captions, under the key source; a video without them gets an empty transcript. Results are cached on disk by video id. download_yt saves a video’s audio as mp3, which needs ffmpeg installed, or its video as mp4. All three accept verify=False to skip certificate checks, which helps behind a proxy that rewrites HTTPS.

One function for every source

read accepts every kind of target the readers above handle and returns the same seven fields for all of them: ok, kind, title, source, text, skipped and meta. This lets a program that collects or indexes sources treat web pages, PDFs, arXiv papers, YouTube videos, GitHub content and local files alike.

what_is decides which reader a target needs. A path that exists on disk wins over every URL rule, so a local file named pdf is read from disk rather than fetched. A GitHub URL containing /blob/ is one file (ghfile) rather than a whole repository (github). Any other http or https URL is a web page. A failed read returns ok=False with the reason in skipped; only a target that is none of these kinds raises ValueError.
