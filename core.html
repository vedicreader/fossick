core

Downloading pages, turning them into markdown, crawling sites, and reading arXiv, GitHub, YouTube and PDF sources

This module holds everything fossick does with a single URL or file. fetch downloads a page and to_md turns its HTML into markdown. crawl follows links from one page to the next. find_xhr and paginate_api find the JSON API a page loads its data from and read it directly. Separate readers handle arXiv papers, GitHub repositories, YouTube videos and PDFs, and read, at the end of the notebook, picks the right one for any target.

Turning HTML into markdown

A downloaded page is mostly markup that a reader does not need: navigation bars, scripts, styles and advertisements. to_md strips that away and returns the text as markdown. It accepts either a raw HTML string or a response returned by fetch, and with sel it converts only the part of the page that matches a CSS selector, such as sel='article'. html2md does the same for a string alone, and html_title returns a document’s title.

Refusing private addresses

A program that fetches URLs chosen by an AI agent can be made to fetch addresses inside your own network. Examples are a router’s admin page and a cloud server’s metadata service, which hands out credentials. This attack is called server-side request forgery. check_url refuses any URL that is not http or https. It refuses host names such as localhost and metadata.google.internal. It refuses any host that resolves to a private, loopback, link-local or other non-public address. It raises BlockedURL. The message names two ways to allow such a URL. Pass allow_private=True to one call, or set the environment variable FOSSICK_ALLOW_PRIVATE=1 for the whole process. get_page, fetch, http_get and http_post run this check first. http_page does not.

local_host answers a smaller question with no network call: does a host name or an address name this computer or the local network? It is True for localhost, for a name that ends in .local, .lan, .internal, .localhost or .home.arpa, for a name with no dot such as intranet, and for an address that is not global, also in a short form such as 127.1. A program can use it to refuse a link at once, before check_url looks the name up. check_url does not call it: a name with no dot that resolves to a public address stays allowed.

The check looks up the host name, and then the download looks it up again. The two lookups can get different answers. A person who controls the DNS for a name can give a public address to the check and 127.0.0.1 to the download. This attack is called DNS rebinding. To stop it, the plain HTTP path of get_page gives libcurl the addresses that the check approved, with the libcurl option CURLOPT_RESOLVE. libcurl then connects only to those addresses and does not look up the name again. The plain path also follows redirects itself. Before it connects to a new URL, it checks and pins the address of that URL in the same way. It does not send cookies, auth or credential headers that you supplied to a different host.

Some paths cannot pin the address, and keep only the first check. Through a proxy, also one that is set in the environment, the proxy looks up the name. The browser paths (heavy, stealthy, session, and auto=True after the plain step) check only the first URL. The browser does its own lookups, follows redirects, and loads scripts and images from other addresses with no check. For URLs that you do not trust, use the plain path.

Downloading one page

get_page runs check_url, then downloads the page in one of four ways. By default it sends a plain HTTP request. heavy=True loads the page in a headless browser so that its JavaScript runs. stealthy=True uses scrapling’s stealth browser, which is built to pass bot checks such as Cloudflare’s. session=True uses the logged-in Chrome described in fossick.cdp, with its cookies. The browsers load on first use. When they cannot load, get_page raises BrowserUnavailable.

http_get and http_post are get_page with the method set and a 30 second timeout. All of them verify TLS certificates by default. Pass verify=False only for a host you trust that has a bad certificate. http_page sends a plain request with GET, POST, PUT or DELETE and skips the address check. Use http_page only for URLs your own code chose. Most callers need fetch, below.

Two optional limits apply to the plain path. max_bytes stops the download when the body becomes larger than that number of bytes, and raises TooLarge. A server that sends gigabytes then cannot fill the memory before to_md runs. max_recv_speed sets the highest download speed, in bytes per second. Both limits are off by default. The browser paths do not use them. http_page also takes max_bytes, and curl_options for other libcurl options.

Some networks inspect TLS traffic with their own root certificate. curl_cffi does not use the system keychain, so on such a machine a check of the certificate fails with curl: (60) ... unable to get local issuer certificate. Give the plain path a CA bundle file that holds the normal roots and the inspection root. Pass ca_bundle= or verify= with the path of the file, or set one of the environment variables SSL_CERT_FILE, CURL_CA_BUNDLE or REQUESTS_CA_BUNDLE. fossick reads them in that order, on each request. It uses the first one that names a file. On macOS, when none of these is set, fossick uses the system keychain. It reads the certificates of the system keychains once with security find-certificate, adds them to certifi’s roots, and keeps the result in its cache folder for one day. An inspection root that your company put in the system keychain then works with no setup. The bundle applies only when verification is on: with verify=True, as http_get sets it, or with ca_bundle=. fossick never turns verification off. On other systems, when none of these is set, nothing changes.

fetch

Most code downloads a page with fetch. It wraps get_page and returns scrapling’s response object with two attributes added. html holds the page, or only the part matching sel. xhr holds the background requests recorded when capture_xhr=True. The response also has status, url, and a json() method for JSON replies.

auto=True tries the download methods in turn: plain HTTP, then the headless browser, then the stealth browser, then the stealth browser through the logged-in Chrome. A bot wall is a page that asks for a verification step instead of showing the requested content. auto=True stops at the first response that is not a bot wall. It records the method that worked in tier, or 'blocked' if none did. It records each failed attempt and its reason in errs.

browser_session downloads many pages with one browser. Starting a browser takes seconds. browser_session opens one browser for the length of a with block and gives you a fetch-like function that reuses it.

auto=True can end in the logged-in Chrome. That last method connects to the debug Chrome on port 9223, starts it if it is not running, and sends the cookies that Chrome has for the site. This is correct for a page that you want to read as yourself. It is not correct for a URL that comes from a web page, a document or another person. Such a URL can make your logged-in browser open a page with your cookies. When you do not trust the URL, pass auto=False. This is the default for fetch, but not for read. With auto=False, and without heavy, stealthy, session or capture_xhr, no function in this module starts a browser or connects to port 9223. This includes get_pdf and its proof-of-work step, read_arxiv, read_gh_file, crawl and read. The plain path always checks redirects: follow_redirects is 'safe' by default, and fossick checks and pins each step itself. The section Fetching untrusted URLs, near the end of this notebook, tests this.

fetch can remember. All three settings are off by default, and a call that does not set them makes a new request each time.

  • cache=900 keeps a response with status 200 for 900 seconds, in memory. A later call with the same arguments gives the same response object, with no request. The memory keeps at most MEM_MOST (256) responses, and the one used longest ago goes first.
  • per_host=True sends one request at a time to each host. A second thread that asks the same host waits until the first has its response.
  • remember_blocks=(401, 403, 429) remembers a host that gave one of these statuses, for cache seconds. The call that gets the status returns the response as usual. A later call to that host raises BlockedURL at once, with no request. This setting needs cache.

forget() clears the kept responses, the hosts that refused, and the locks. It also clears the results that search(cache=) keeps.

def forget():

Clear what fetch and search remember: the kept responses and searches, the hosts that refused, and the lock of each host.

The tests below give fetch a fake get_page, so they need no network. The fake records each request, gives status 429 for one path, and can wait at a barrier, so that a test can see two requests at the same time.

from types import SimpleNamespace
_asked, _busy, _most, _gate, _real_get_page = [], [0], [0], [None], get_page
def get_page(url, **kw):
    _asked.append(url); _busy[0] += 1; _most[0] = max(_most[0], _busy[0])
    try:
        if _gate[0]: _gate[0].wait()
        else: time.sleep(0.05)
        return SimpleNamespace(status=429 if url.endswith('/busy') else 200, html_content='<p>hi</p>', url=url)
    finally: _busy[0] -= 1
_e = 'https://example.com'
try:
    forget()
    fetch(f'{_e}/a'); fetch(f'{_e}/a')                        # the defaults: no memory, a request each time
    test_eq((_asked, _mem['pages'], _mem['blocks']), ([f'{_e}/a'] * 2, {}, {}))

    _asked.clear()
    r1 = fetch(f'{_e}/a', cache=0.3); r2 = fetch(f'{_e}/a', cache=0.3)
    test_is(r1, r2); test_eq(len(_asked), 1)                  # a cache hit
    fetch(f'{_e}/a', timeout=5, cache=0.3); test_eq(len(_asked), 2)   # other arguments: another entry
    time.sleep(0.35); fetch(f'{_e}/a', cache=0.3); test_eq(len(_asked), 3)   # the time is over

    _asked.clear(); forget()
    _most_was, MEM_MOST = MEM_MOST, 2
    try:
        for u in ('x', 'y', 'x', 'z', 'x', 'y'): fetch(f'{_e}/{u}', cache=60)
        test_eq(_asked, [f'{_e}/{u}' for u in ('x', 'y', 'z', 'y')])   # x was used last, so y went first
    finally: MEM_MOST = _most_was

    _asked.clear(); forget()
    test_eq(fetch(f'{_e}/busy', cache=60, remember_blocks=(429,)).status, 429)   # the first 429 comes back as usual
    test_fail(lambda: fetch(f'{_e}/other', cache=60, remember_blocks=(429,)), contains='answered 429')
    test_eq(_asked, [f'{_e}/busy'])                           # no request for the second call
    fetch(f'https://example.org/other', cache=60, remember_blocks=(429,))   # another host is asked
    forget(); fetch(f'{_e}/other', cache=60, remember_blocks=(429,))       # forget() clears the refusal
    test_eq(len(_asked), 3); assert _mem['pages']
    forget(); test_eq((_mem['pages'], _mem['blocks'], _mem['hosts']), ({}, {}, {}))
    test_fail(lambda: fetch(f'{_e}/a', remember_blocks=(429,)), contains='needs cache')

    def _two(**kw):
        _most[0] = 0
        ts = [threading.Thread(target=fetch, args=(f'{_e}/{i}',), kwargs=kw) for i in range(2)]
        for t in ts: t.start()
        for t in ts: t.join()
        return _most[0]
    test_eq(_two(per_host=True), 1)                           # two threads on one host: one after the other
    _gate[0] = threading.Barrier(2, timeout=5)
    try: test_eq(_two(), 2)                                   # the control: with no per_host they overlap
    finally: _gate[0] = None
finally: get_page = _real_get_page; forget()

Bot walls

Many sites put a challenge page in front of their content for visitors they think are scripts. Cloudflare’s “Just a moment” page and the Anubis proof-of-work page are common examples. The challenge often arrives with status 200, so it looks like a successful download. fossick treats a response as blocked when its status is 401, 403, 429, 503 or 530, when its HTML contains the marker of a known challenge or captcha widget, or when it is a 200 response with less than 200 characters of HTML. The tests below check these rules, including that a page which only mentions the word captcha is not counted as blocked.

The cells after that run against real sites and are not run by the tests. They show a Cloudflare and an Anubis wall being detected, auto=True stopping at the plain tier for a page that needs nothing more, browser_session reusing one browser for two pages, and session=True going through the logged-in Chrome.

# A site behind Cloudflare: a plain fetch hits the bot wall, and _blocked() flags it for escalation
cf = fetch('https://www.scrapingcourse.com/cloudflare-challenge', verify=False)
assert cf.status == 403, f'expected a Cloudflare 403 challenge, got {cf.status}'
assert _blocked(cf) is True            # fetch(auto=True) escalates from here (heavy -> stealthy -> session)
print('cloudflare:', cf.status, '| blocked?', _blocked(cf))
# A site behind Anubis (proof-of-work bot wall): _blocked() now recognizes it, so fetch(auto=True) escalates
an = fetch('https://anubis.techaro.lol/', verify=False)
assert 'making sure' in an.html.lower(), 'expected the Anubis challenge page'
assert _blocked(an) is True            # Anubis markers are in _BLOCK_MARKERS -> auto escalates past this wall
print('anubis wall detected by _blocked?', _blocked(an))
# regression: a normal page that merely *mentions* captcha must NOT read as a bot wall.
# Wikipedia embeds hCaptcha config keys in its page JS -- the word is there, but there's no challenge widget.
wiki = fetch('https://en.wikipedia.org/wiki/Anubis', verify=False)
assert wiki.status == 200 and 'captcha' in wiki.html.lower()   # the word IS present on the page...
assert _blocked(wiki) is False   # ...but _BLOCK_MARKERS matches captcha *widgets* (g-recaptcha/h-captcha/...), not the word
# fetch(auto=True): walks plain->heavy->stealthy->session, stops at the first unblocked tier, tags .tier
plain = fetch('https://example.com', auto=True, verify=False)
assert plain.status == 200 and plain.tier == 'plain'   # a static page needs no escalation
print('example.com ->', plain.tier)
# browser_session(): open ONE browser, reuse it across fetches (skips per-URL relaunch)
with browser_session() as bf:
    a = bf('https://example.com')
    b = bf('https://httpbin.org/html')
assert a.status == 200 and b.status == 200
assert len(a.html) > 0 and len(b.html) > 0
# fetch(session=True): route through the persistent debug Chrome, reusing its logged-in cookies
pg = fetch('https://httpbin.org/headers', session=True)
assert pg.status == 200
print(pg.html[:200])

Crawling and batches

crawl visits pages breadth-first, starting from one URL and following the links that match follow_sel, until it has visited max_pages pages. By default it stays on the starting site. It returns the responses that came back with status 200, and a page that fails to download is reported and skipped. delay waits between requests so as not to load a small site heavily. For crawls with heavy or stealthy, one browser is kept open for the whole crawl unless reuse=False.

keep filters the links before they go into the queue. It gets each link as an absolute URL, made from the address of the page after its redirects, and returns True to queue it. Use it to keep a crawl inside one folder of a site. The start page is always read.

arXiv HTML, with the maths

arXiv also shows most new papers as an HTML page that LaTeXML makes from the TeX source. read_arxiv_html reads that page with one fetch, plain HTTP by default. It returns title, text, figures and url. In text, each formula is its TeX: $…$ inline and $$…$$ for a block, so a reader can show the maths and quote it word for word. In the PDF text, the same formula is a run of loose symbols, such as “1 dk”.

arxiv_md does the conversion. Each formula becomes a token first, so that the markdown step cannot change its TeX. Then each token becomes its TeX. A numbered equation, which LaTeXML puts in a table, becomes one line with its number. A $ in the text becomes \$, so it does not start a formula. Scripts, styles, forms, menus and the table of contents are removed.

figures holds the links of the images in the HTML folder of the paper, at most 30, with no .. in the path, also in percent codes. read_arxiv_html gives None on any error, for a status other than 200, for a page that is not on arxiv.org after the redirects, for a page that is not a LaTeXML paper, and for a page with less than 200 characters of text. Then read the PDF. read(target, html=True) does that for an arXiv target: it reads the HTML page first and the PDF when there is no HTML page.

The tests use a saved, cut-down LaTeXML page and a fake fetch, so they need no network.

gh_clone returns a local copy of a repository. The first call clones it into fossick’s cache folder, in a folder named owner__repo. It clones over HTTPS only, and never asks for a password. Pass ssh=True to try SSH after HTTPS, for a private repository and an SSH key. SSH then runs in batch mode, so it fails at once when it needs a passphrase. The clone is shallow: it gets only the latest commit. Pass depth=None for the full history, or a different number of commits. timeout is the time limit for each git command, in seconds. When git takes longer, fossick stops git, removes the part-made folder and raises TimeoutError. Later calls fetch the clone and reset it to the latest commit. Git runs with /dev/null as stdin and never reads the caller’s terminal. fossick gives git its own environment and does not change os.environ. fossick refuses a target that starts with -, and puts -- before the URL, so that git cannot read a URL as an option. gh_clone returns a local path unchanged. Code that accepts a repository therefore accepts a folder on disk. read_gh_repo reads files from that clone and returns {path: text}. By default it reads the README, pyproject.toml and every Python file. It caches its results for an hour. read_gh_file downloads one file as raw text from its GitHub page URL. It returns source code exactly as written. It converts the file to markdown only when GitHub serves HTML.

gh_repo reads the owner/name of a repository from a github.com link, also a link to a file, an issue or a commit, from an SSH remote, or from the shorthand owner/name. It makes no network call and does not check that the repository exists. The shorthand matches any text of that shape, such as and/or, so a program that reads prose must filter what it gets.

pattern can be a regular expression, such as .*products.*, or a shell-style glob, such as *products*. compile_pattern accepts both: it tries the text as a regular expression and, when that is invalid, reads it as a glob.

These three functions use yt-dlp. search_yt searches YouTube and returns a list of result dictionaries. read_yt returns one video’s details and its transcript under the key source. One function for every source

read accepts every kind of target the readers above handle and returns the same seven fields for all of them: ok, kind, title, source, text, skipped and meta. A program can treat web pages, PDFs, arXiv papers, YouTube videos, GitHub content and local files alike.

what_is decides which reader a target needs. An arXiv id is a new id such as 1706.03762, an old id such as hep-th/9901001, or an arxiv: id. A path that exists on disk wins over every URL rule, so a folder named hep-th/9901001 is a folder, and a local file named pdf is read from disk rather than fetched. A GitHub URL containing /blob/ is one file (ghfile) rather than a whole repository (github). Any other http or https URL is a web page. A failed read returns ok=False with the reason in skipped. Only a target that is none of these kinds raises ValueError.

what_is reads the host of a URL to find arXiv and YouTube links, not the full text of the URL. https://docs.example.dev/youtube.com-guide is a web page, not a YouTube video.

Fetching untrusted URLs

A program that reads links from web pages, documents or messages fetches URLs that another person can choose. For these URLs, call fetch, get_pdf and read with auto=False. fossick then uses only plain HTTP. It checks and pins each address, and checks each redirect again. max_bytes can limit the size of each download.

The tests below use a small web server in this process, on 127.0.0.1. The address check refuses 127.0.0.1, so _public_loopback makes the check count it as public for the length of a test.
