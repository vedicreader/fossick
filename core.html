core

Downloading pages, turning them into markdown, crawling sites, and reading arXiv, GitHub, YouTube and PDF sources

This module handles one URL or file at a time. fetch downloads a page. to_md converts HTML to markdown. crawl follows links between pages. find_xhr and paginate_api find and read the JSON API that supplies a page’s data. Other readers handle arXiv papers, GitHub repositories, YouTube videos and PDFs. read selects the reader for each target.

Turning HTML into markdown

A downloaded page contains markup that a reader does not need, such as navigation bars, scripts, styles and advertisements. to_md removes this markup and returns markdown. It accepts an HTML string or a response from fetch. With sel, it converts only the part that matches a CSS selector, such as sel='article'. html2md converts an HTML string. html_title returns the document title.

By default, to_md and html2md use readability. This article extractor finds the main article and removes the surrounding content. It can also remove content that you need, such as section headings. Refusing private addresses

An AI agent can choose the URLs that a program fetches. Then a person can make the program fetch addresses inside your own network. Examples are the admin page of a router and the metadata service of a cloud server. A metadata service gives out credentials. This attack is called server-side request forgery. check_url refuses a URL that is not http or https. It refuses host names such as localhost and metadata.google.internal. It refuses a host that resolves to a private, loopback, link-local or other non-public address. For each refusal, it raises BlockedURL. The message names two ways to allow such a URL. To allow it for one call, pass allow_private=True. To allow it for the whole process, set the environment variable FOSSICK_ALLOW_PRIVATE=1. get_page, fetch, http_get and http_post run this check first. http_page does not run it.

local_host tells you if a host name or an address names this computer or the local network. It makes no network call. It returns True for these hosts:

  • localhost
  • a name that ends in .local, .lan, .internal, .localhost or .home.arpa
  • a name with no dot, such as intranet
  • an address that is not global, also in a short form such as 127.1

A program can use local_host to refuse a link before check_url looks up the name. check_url does not call local_host. Thus check_url allows a name with no dot when that name resolves to a public address.

The check looks up the host name. Then the download looks it up again. The two lookups can get different answers. A person who controls the DNS for a name can give a public address to the check and 127.0.0.1 to the download. This attack is called DNS rebinding. To stop it, the plain HTTP path of get_page gives libcurl the addresses that the check approved. It uses the libcurl option CURLOPT_RESOLVE. libcurl then connects only to those addresses. It does not look up the name again. The plain path also follows redirects itself. Before it connects to a new URL, it checks and pins the address of that URL in the same way. It does not send your cookies, auth or credential headers to a different host.

Some paths cannot pin the address. They keep only the first check. Through a proxy, the proxy looks up the name. This is also true for a proxy that the environment sets. The browser paths check only the first URL. These paths are heavy, stealthy, session, and auto=True after the plain step. The browser does its own lookups and follows redirects with no check. It also loads scripts and images from other addresses with no check. For URLs that you do not trust, use the plain path.

Downloading one page

get_page runs check_url. Then it downloads the page in one of four ways. By default, it sends a plain HTTP request. heavy=True loads the page in a headless browser, which runs the JavaScript of the page. stealthy=True uses the stealth browser of scrapling. This browser is made to pass bot checks, such as the checks of Cloudflare. session=True uses the logged-in Chrome of fossick.cdp, with its cookies. The browsers load on first use. When they cannot load, get_page raises BrowserUnavailable.

http_get and http_post are get_page with a set method and a 30 second timeout. All of them verify TLS certificates by default. Pass verify=False only for a host that you trust and that has a bad certificate. http_page sends a plain GET, POST, PUT or DELETE request. It does not run the address check. Use http_page only for URLs that your own code chose. Most callers need fetch, which comes next.

Two optional limits apply to the plain path. max_bytes stops the download when the body is larger than that number of bytes. Then it raises TooLarge. With this limit, a server that sends gigabytes cannot fill the memory before to_md runs. max_recv_speed sets the highest download speed, in bytes per second. Both limits are off by default. The browser paths do not use them. http_page also takes max_bytes. It takes curl_options for other libcurl options.

Some networks inspect TLS traffic with their own root certificate. curl_cffi does not use the system keychain. On such a network, the certificate check fails with curl: (60) ... unable to get local issuer certificate. To fix this, give the plain path a CA bundle file. The file must hold the normal roots and the inspection root. Pass the path of the file as ca_bundle= or verify=. Or set one of the environment variables SSL_CERT_FILE, CURL_CA_BUNDLE or REQUESTS_CA_BUNDLE. fossick reads them in that order, on each request. It uses the first one that names a file.

On macOS, when none of these is set, fossick uses the system keychain. It reads the certificates of the system keychains with security find-certificate. It adds them to the roots of certifi. It keeps the result in its cache folder for one day. Thus an inspection root that your company put in the system keychain works with no setup. On other systems, when none of these is set, curl uses its own roots.

The bundle applies only when verification is on. Verification is on with verify=True, which http_get sets, or with ca_bundle=. fossick does not turn verification off by itself. Only verify=False from the caller turns it off.

fetch

Most code downloads a page with fetch. It calls get_page and returns the scrapling response object with two more attributes. html holds the page, or only the part that matches sel. xhr holds the background requests that fossick records when capture_xhr=True. The response also has status, url, and a json() method for JSON replies.

auto=True tries the download methods in this order:

  1. plain HTTP
  2. the headless browser
  3. the stealth browser
  4. the stealth browser through the logged-in Chrome

A bot wall is a page that asks for a verification step instead of the content that you asked for. auto=True stops at the first response that is not a bot wall. It records the method that worked in tier. When no method worked, tier is 'blocked'. It records each failed attempt and its reason in errs.

browser_session downloads many pages with one browser. A browser takes some seconds to start. browser_session keeps one browser open for the length of a with block. It gives you a function like fetch that uses this browser for each page.

auto=True can end in the logged-in Chrome. The last method connects to the debug Chrome on port 9223. It starts that Chrome when it is not running. It sends the cookies that Chrome has for the site. This is correct for a page that you want to read as yourself. It is not correct for a URL from a web page, a document or another person. Such a URL can make your logged-in browser open a page with your cookies.

When you do not trust the URL, pass auto=False. auto=False is the default for fetch. It is not the default for read. With auto=False, and without heavy, stealthy, session or capture_xhr, no function in this module starts a browser. No function connects to port 9223. This includes get_pdf and its proof-of-work step, read_arxiv, read_gh_file, crawl and read. The plain path always checks redirects. follow_redirects is 'safe' by default. fossick checks and pins each redirect itself. The section Fetching untrusted URLs, near the end of this notebook, tests this.

fetch can keep responses in memory. Three settings control this. All three are off by default. A call that does not set them sends a new request each time.

  • cache=900 keeps a response with status 200 in memory for 900 seconds. A later call with the same arguments returns the same response object, with no request. The memory keeps at most MEM_MOST (256) responses. When it is full, the response used longest ago goes first.
  • per_host=True sends one request at a time to each host. When two threads ask the same host, the second waits until the first has its response.
  • remember_blocks=(401, 403, 429) remembers a host that gave one of these statuses, for cache seconds. The call that gets the status returns the response as usual. A later call to that host raises BlockedURL at once, with no request. This setting needs cache.

forget() clears the kept responses, the hosts that refused, and the locks. It also clears the results that search(cache=) keeps.

forget

def forget():

Clear the cached responses, searches, refused hosts and host locks.

The tests below give fetch a fake get_page, so they need no network. The fake records each request. It gives status 429 for one path. It can wait at a barrier, which lets a test see two requests at the same time.

from types import SimpleNamespace
_asked, _busy, _most, _gate, _real_get_page = [], [0], [0], [None], get_page
def get_page(url, **kw):
    _asked.append(url); _busy[0] += 1; _most[0] = max(_most[0], _busy[0])
    try:
        if _gate[0]: _gate[0].wait()
        else: time.sleep(0.05)
        return SimpleNamespace(status=429 if url.endswith('/busy') else 200, html_content='<p>hi</p>', url=url)
    finally: _busy[0] -= 1
_e = 'https://example.com'
try:
    forget()
    fetch(f'{_e}/a'); fetch(f'{_e}/a')                        # the defaults: no memory, a request each time
    test_eq((_asked, _mem['pages'], _mem['blocks']), ([f'{_e}/a'] * 2, {}, {}))

    _asked.clear()
    r1 = fetch(f'{_e}/a', cache=0.3); r2 = fetch(f'{_e}/a', cache=0.3)
    test_is(r1, r2); test_eq(len(_asked), 1)                  # a cache hit
    fetch(f'{_e}/a', timeout=5, cache=0.3); test_eq(len(_asked), 2)   # other arguments: another entry
    time.sleep(0.35); fetch(f'{_e}/a', cache=0.3); test_eq(len(_asked), 3)   # the time is over

    _asked.clear(); forget()
    _most_was, MEM_MOST = MEM_MOST, 2
    try:
        for u in ('x', 'y', 'x', 'z', 'x', 'y'): fetch(f'{_e}/{u}', cache=60)
        test_eq(_asked, [f'{_e}/{u}' for u in ('x', 'y', 'z', 'y')])   # x was used last, so y went first
    finally: MEM_MOST = _most_was

    test_eq(fetch(f'{_e}/busy', cache=60, remember_blocks=(429,)).status, 429)   # the first 429 comes back as usual
    test_fail(lambda: fetch(f'{_e}/other', cache=60, remember_blocks=(429,)), contains='answered 429')

Bot walls

Many sites show a challenge page instead of their content when they think that the visitor is a script. Two common examples are the “Just a moment” page of Cloudflare and the Anubis proof-of-work page. The challenge often has status 200. Thus it looks like a successful download. fossick treats a response as blocked in three cases:

  • its status is 401, 403, 429, 503 or 530
  • its HTML contains the marker of a known challenge or captcha widget
  • it has status 200 and less than 200 characters of HTML

The tests below check these rules. They also check that a page which only contains the word captcha is not blocked.

The cells after the tests use real sites. The test run does not run them. They show these results:

  • fossick finds a Cloudflare wall and an Anubis wall.
  • auto=True stops at the plain tier for a page that needs no browser.
  • browser_session uses one browser for two pages.
  • session=True downloads through the logged-in Chrome.
# A site behind Cloudflare: a plain fetch hits the bot wall, and _blocked() flags it for escalation
cf = fetch('https://www.scrapingcourse.com/cloudflare-challenge', verify=False)
assert cf.status == 403, f'expected a Cloudflare 403 challenge, got {cf.status}'
assert _blocked(cf) is True            # fetch(auto=True) escalates from here (heavy -> stealthy -> session)
print('cloudflare:', cf.status, '| blocked?', _blocked(cf))
# A site behind Anubis (proof-of-work bot wall): _blocked() now recognizes it, so fetch(auto=True) escalates
an = fetch('https://anubis.techaro.lol/', verify=False)
assert 'making sure' in an.html.lower(), 'expected the Anubis challenge page'
assert _blocked(an) is True            # Anubis markers are in _BLOCK_MARKERS -> auto escalates past this wall
print('anubis wall detected by _blocked?', _blocked(an))
# regression: a normal page that merely *mentions* captcha must NOT read as a bot wall.
# Wikipedia embeds hCaptcha config keys in its page JS -- the word is there, but there's no challenge widget.
wiki = fetch('https://en.wikipedia.org/wiki/Anubis', verify=False)

assert _blocked(wiki) is False   # ...but _BLOCK_MARKERS matches captcha *widgets* (g-recaptcha/h-captcha/...), not the word
# fetch(auto=True): walks plain->heavy->stealthy->session, stops at the first unblocked tier, tags .tier
plain = fetch('https://example.com', auto=True, verify=False)
assert plain.status == 200 and plain.tier == 'plain'   # a static page needs no escalation
print('example.com ->', plain.tier)
# browser_session(): open ONE browser, reuse it across fetches (skips per-URL relaunch)

Crawling and batches

crawl visits pages breadth-first. It starts at one URL and follows links that match follow_sel. It stops after visiting max_pages pages. By default, it stays on the starting site. It returns responses with status 200. It reports and skips a page that it cannot download. delay waits between requests. Use it to reduce the load on a small site. For crawls with heavy or stealthy, one browser stays open for the whole crawl unless reuse=False.

keep filters links before it adds them to the queue. It receives each link as an absolute URL. The URL uses the page address after redirects. Return True to queue the link. Use keep to limit a crawl to one site folder. crawl always reads the start page.

arXiv HTML, with the maths

arXiv shows most new papers as HTML pages made by LaTeXML from TeX source. read_arxiv_html reads this page with one fetch. It uses plain HTTP by default. It returns title, text, figures and url. In text, each formula uses TeX. Inline formulas use $…$. Block formulas use $$…$$. A PDF can show the same formula as loose symbols, such as “1 dk”.

arxiv_md converts the page. It first replaces each formula with a token. This prevents the markdown conversion from changing the TeX. It then replaces each token with its TeX. A numbered equation becomes one line with its number. LaTeXML puts numbered equations in a table. The conversion escapes $ in the text as \$. This prevents it from starting a formula. The conversion removes scripts, styles, forms, menus and the table of contents.

figures contains up to 30 image links from the paper’s HTML folder. The paths contain no .., including percent-encoded values. read_arxiv_html returns None in these cases:

  • an error
  • a status other than 200
  • a page outside arxiv.org after redirects
  • a page that is not a LaTeXML paper
  • text shorter than 200 characters

Then read the PDF. read(target, html=True) does this for an arXiv target. It reads the HTML page first. It reads the PDF when no HTML page exists.

The tests use a saved, shortened LaTeXML page and a fake fetch, so they need no network.

Many modern pages are almost empty when they arrive. Then JavaScript loads their data with background requests. These requests are called XHR or fetch calls. They usually return JSON. You can read that JSON directly instead of the rendered page.

find_xhr loads a page in a headless browser and records the background requests that the page makes. It returns each request whose URL matches pattern. Each result is a dictionary with url, content_type and the decoded data. With session=True, find_xhr records the requests through the logged-in Chrome. Then each result also has a capture.

replay_xhr sends a captured request again as a plain HTTP call with the cookies of the browser. Use it to call an API that needs a login, with no open browser.

pattern can be a regular expression, such as .*products.*, or a shell-style glob, such as *products*. compile_pattern accepts both forms. It first tries the text as a regular expression. If that fails, it treats the text as a glob.

read accepts each kind of target that the readers above accept. For each target, it returns the same seven fields: ok, kind, title, source, text, skipped and meta. what_is finds the reader for a target. An arXiv id is a new id such as 1706.03762, an old id such as hep-th/9901001, or an arxiv: id. A path that exists on disk wins over every URL rule. A failed read returns ok=False with the reason in skipped. read raises ValueError only for a target that is none of these kinds.

To find arXiv and YouTube links, what_is reads the host of a URL. It does not search the full text of the URL. Thus https://docs.example.dev/youtube.com-guide is a web page, not a YouTube video.

Installing the agent skill

fossick includes a SKILL.md file that tells coding agents how to use it. mv_skill_md copies it to .agents/skills/fossick/ at the root of the current git repository found by repo_root. It also copies it to .claude/skills/fossick/ under the working directory. The default dry_run=True prints the destination and copies nothing. The fossick install command copies the file.
