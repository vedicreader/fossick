Quality

Choose useful search results and searches

A search engine ranks pages by how well they match a query. That ranking does not show which pages are useful to read. A question about building rules in Australia can return five cost guides from one trade directory before the government page that sets the rules. A programming question can return sites that copy Stack Overflow answers.

This module reorders results before it downloads a page. It does four things:

  • It removes copycat sites.
  • It moves authoritative sources for the question towards the top.
  • It limits the number of results from one website near the top.
  • It splits a question with several parts into one search for each part.

research in fossick.search calls curate when curated=True. This is the default. It also uses plan and interleave. You can use each function with a list of result dictionaries that has an href or url.

Identify a site from a URL

Two URLs belong to the same site when they share a registrable domain. This is the part of the name that someone registered. docs.python.org and www.python.org both belong to python.org. The registrable domain usually has the last two parts of the host name. Some registries sell names one level down. For example, bbc.co.uk and nsw.gov.au have three parts. MULTI_LABEL_SUFFIXES lists these registry endings for the countries that fossick handles. host returns a URL host name in lower case without www.. registrable_domain returns the site.

Use one key for each page

The same page can have several URLs. The URLs can differ by www., a trailing slash, or tracking parameters such as utm_source. norm_url reduces a URL to one key. It removes the scheme, www., the fragment, tracking parameters, a default port, and a trailing slash. It sorts the query parameters. A non-default port stays in the key. interleave, cluster_sources, and diversity use this key to identify the same page.

Match authority to the question

The best source depends on the question. A government site is authoritative for a law question. Documentation is authoritative for a library question. A forum is useful for user opinions. DOMAIN_RULES lists the sites to move up (boost) and down (demote) for each question kind. The kinds are docs, policy, release, security, and community.

domain_matches checks a host name against a rule. A rule has one of four forms:

Rule Matches Example
Ends in a dot Host names that start with it docs.
Starts with a dot The ending itself and every host under it .gov.au
Contains a / Only the host name before the /, with no subdomains github.com/advisories
Any other text That domain and its subdomains sec.gov

Only a rule that ends in a dot matches the start of a host name. openai.com.evil.example does not match openai.com. blocked_matches applies the last form to a blocked list.

Classify the question

classify reads the question kind from cue words in INTENT_CUES. “regulation” and “permit” indicate policy. “release notes” indicates release. classify returns the kind with the most cue matches. It returns None when the query has no cues or when two kinds tie. With None, curate does not reorder results by authority.

Remove copycat sites

SPAM_MIRRORS lists sites that copy content from other sites. Examples include Stack Overflow scrapers and GitHub mirrors. These sites add nothing to the original. Several search engines can rank them highly because they target each engine.

drop_spam removes results from these sites and from domains in blocked. It returns the remaining results and the removed domains. allowed keeps a domain even when a list contains it. It also keeps subdomains of that domain.

A query that contains site:reddit.com already selects a site. site_domains returns the domains named by site: in a query. For this query, curate skips copycat removal and the per-site limit. curate still reorders results by authority.

Split one question into searches

A question such as “I want to rebuild my garage in australia, cheap options, what is the regulation on it, material options” asks three things. One search for all three parts mostly finds pages about the first part. plan creates one search for each part.

plan removes openings such as “I want to” (LEAD_INS) and empty phrases (FILLER). It splits the rest at commas, semicolons, question marks, and words such as “and”. It adds the topic words from the first part to each later part. Each search still contains “garage australia”. The original question is always the first search.

plan returns [q] when it has nothing to split. The table lists these conditions.

Condition Result
max_queries is below 2 [q]
The query has fewer than min_words words [q]
The query has site: [q]
The query has only one part [q]
The later parts add no new words to the first [q]

max_queries limits the number of searches. rewrite is a function that takes the question and returns a list of searches. You can use a language model for this function. When you pass rewrite, plan uses it instead of these rules. facets returns the parts as lists of topic words.

interleave merges result lists from several searches. It takes one result from each list in turn. It keeps a page that several searches found only once. For a duplicate page, it joins the queries lists. This gives each question part its own sources. Merging by score would favour a general guide over a source that answers one part.

Reorder results

authority_rerank moves results from sites that DOMAIN_RULES boosts for a question kind to the front. It moves results from sites that DOMAIN_RULES demotes towards the back. cap_per_domain keeps at most max_per results from each site near the top. It moves the remaining results to the end in their original order. A list with fewer than three results stays unchanged.

Neither function drops a result. Results that do not move keep their order. Both functions return the reordered list and a second value. authority_rerank returns a report dictionary with intent, applied, boosted, and demoted. cap_per_domain returns the number of results moved to the end.

Count stories, not URLs

Ten results can represent one story. For example, nine sites can reprint one news agency report. cluster_sources groups results with the same norm_url key or with mostly shared text.

shingles returns the set of three-word sequences in a text. jaccard divides the overlap of two sets by their union. cluster_sources applies jaccard to the shingles from each result title and text. Two results with a similarity at or above threshold are one story. The default threshold is 0.6. The grouping is transitive. When A matches B and B matches C, all three results form one group. Each group uses its first input member as its name.

independence returns the groups with a score. The score rises with the number of separate stories and sites. The result also lists its limits. Two sites that rewrite one press release in their own words do not share enough text to form one group.

Describe a result list

diversity describes a list without changing it. The result has these keys:

Key Meaning
n, domains Number of results and number of sites
dominant_domain The site with the most results, and its share of the results
dup_urls Number of results whose norm_url key repeats an earlier one
near_dups Number of pairs of results that read alike
sources Number of separate stories
score A number from 0 to 1. A higher number means a more varied list.

The score is the weighted sum of three components.

Component Weight
Share of separate sites 0.5
Share of unique URLs 0.3
Share of pairs that do not read alike 0.2

snippet_similarity returns the Jaccard similarity of the three-word sequences of two texts.

source

curate

curate runs these steps in order:

  1. drop_spam removes copycat sites.
  2. authority_rerank reorders by authority for the kind of question. classify reads the kind from the query, or you pass intent. intent=None skips this step.
  3. cap_per_domain applies the per-site limit. max_per_domain=0 skips this step.
  4. diversity describes the result.

A query with site: skips steps 1 and 3. curate returns the reordered results and a report of what each step did. With rerank=False it returns the results untouched. The report then has dropped=[], demoted=0 and authority=None, and still has intent and diversity.

source

curate

def curate(
    q:str, # the query, read for intent and `site:` constraints
    hits:list, # search hits (dicts with `href`/`url`, `title`, `body`)
    intent:str='auto', # an intent class, 'auto' to classify, or None to skip authority
    max_per_domain:int=2, # per-registrable-domain cap; 0 disables
    blocked:tuple=(), allowed:tuple=(), # extra mirror domains, and rescues from the built-in list
    rerank:bool=True, # False: describe only, return `hits` untouched
)->tuple:

Remove copycat sites, reorder by authority, limit results per site, and return the results with a report.

        dict(href='https://b.invalid/y', title='OpenAI cuts prices', body=_wire),
        dict(href='https://c.invalid/z', title='OpenAI cuts prices', body=_wire),

_chain = [dict(href='https://a.invalid/1', body='alpha beta gamma delta epsilon zeta eta theta'),
